# 四个小项目 · 美术设计优化方案

> 状态：**方案（待确认后执行）** · 2026-10-21
> 四个项目：**乒乓对决 / 返航录 / 落幕查（三角洲价格查询）/ 作品集本站**（游戏合集作为第五个「容器」一并给视觉规范）。

---

## 0. 共同问题（四个项目都有）

| 问题 | 表现 | 影响 |
|---|---|---|
| 没有「一个」强调色 | 每页出现 4–8 种彩色，按钮/标签/链接混用 | 视觉上没有主次，看起来像不同人做的 |
| 图标体系混乱 | emoji（🤝 📱 🚀 🖥️）+ iconify + 内联 SVG 三种并存 | 深色底上 emoji 色差突兀，iOS/安卓渲染不一致 |
| 图片非矢量、非优化 | 项目卡图是 PNG 截图，无统一比例与留白 | 卡片高度参差、加载慢 |
| 缺空态与加载态 | 只考虑「有数据」的界面 | 首屏白屏或抖动 |
| 缺少统一命名 | 资产散落在各仓库 `assets/`、`icon-*`、`logo` | 复用困难，AI 生成资产无处可放 |

## 1. 统一视觉规范（先做，再分项目）

### 1.1 色彩

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#0B0B10` | 全站底 |
| `--surface` | `#14141C` | 卡片 |
| `--line` | `#23232F` | 描边/分隔 |
| `--text` / `--muted` | `#E6E6EE` / `#8E8EA6` | 文本 |
| `--accent` | `#F5A524`（琥珀） | **唯一**强调色：主按钮、当前项、关键数字 |

**项目二级色**（只用于该项目内部的卡图与主题头，不进入全局组件）：

| 项目 | 二级色 | 理由 |
|---|---|---|
| 乒乓对决 | 青 `#2DD4BF`（球台色） | 与琥珀互补，玩家红/蓝仍用项目内的双方色 |
| 返航录 | 深蓝 `#3B82F6` → 紫 `#7C3AED` | 星空/阵营氛围 |
| 落幕查 | 橙红 `#F97316` | 三角洲军用橙 |
| 游戏合集 | 中性 | 只用琥珀 |

### 1.2 字体与字号

- 中文：系统栈（PingFang SC / 微软雅黑）；英文标题：`Inter`（本地 vendor，30 KB）。
- 级差：`12 / 14 / 16 / 20 / 28 / 40 / 64`（px），标题用 `clamp()`。
- 行高：正文 1.65；标题 1.1。

### 1.3 图标

- **全部换成线性 SVG**（stroke 1.5，24×24），统一从一套开源图标集取（Solar / Lucide 均可，MIT）；禁止 emoji 出现在 UI 关键路径（可留在文案里）。
- 每个项目只用 8–12 个图标，**内联**进 HTML，不引 CDN。

### 1.4 资产规范（AI 生成资产也走这一套）

```
assets/
├─ brand/         logo、图标、OG 图
├─ shots/         截图（1920×1200 或 1200×1200，2x）
├─ art/           AI 生成的概念图/贴图（附 ATTRIBUTION.md）
└─ models/        glTF 模型
```

命名：`<项目>_<类型>_<描述>_<版本>.<ext>`，例：`pingpong_shot_menu_v3.webp`。

## 2. 分项目改动

### 2.1 乒乓对决
| 项 | 现状 | 优化 |
|---|---|---|
| 配色 | 项目内已有红/蓝双方色 + 琥珀主按钮 | 保持，但把「主按钮琥珀」与「辅助文字」统一到全局 token |
| 主菜单 | 快速开始卡片信息偏多 | 保留结构，减少一级视觉元素（难度分段控件改 4 个胶囊，未解锁加 🔒 代替置灰） |
| 观众席/器材 | 火柴人 + 平板几何 | 用 Blender 出低模（已有 `assets/models/ping-pong-table.glb`），先只替换**主菜单背景**，不动玩法 |
| 截图 | 只 1 张 | 补 3 张：主菜单 / 对战 / 设置，统一 16:10 取景 |

### 2.2 返航录
| 项 | 现状 | 优化 |
|---|---|---|
| 首页 | 深蓝星空 + 卡片 | 统一 token；阵营色（人类/异形/外星人）固定为 蓝/紫绿/紫，不随皮肤变 |
| 规则文档 | 附件站四个入口 | 新增「规则资料」四卡（正文/速查卡/术语表/流程图），同一套卡片样式 |
| 截图 | 1 张 | 补 3 张：开始页 / 夜间公告 / 复盘 |
| 动效 | 无 | 夜间→白天切换加一次 200ms 渐变，帮助理解阶段变化（只改 CSS） |

### 2.3 落幕查（价格查询）
| 项 | 现状 | 优化 |
|---|---|---|
| 品牌 | logo 有 png/webp | 统一到 `assets/brand/`，出 1 套线性 SVG 图标 |
| 列表 | 数据密集 | 价格涨跌用**红绿 + 箭头**双编码（不只靠颜色），色盲可用 |
| 空态/加载 | 未确认 | 补骨架屏 + 空态图（AI 生成一张即可） |

### 2.4 作品集本站
见 `docs/作品集重构方案.md` §4（token、7 个组件、图片 WebP、图标内联）。

### 2.5 游戏合集（容器）
- 两张大卡用统一模板：图占 60% 高、标题 + 一句 + 3 个能力标签 + 主按钮；
- 两卡之间留 24px，不做分隔线（靠留白分区）。

## 3. AI 美术在这套规范里怎么用

| 环节 | 用什么 | 限制 |
|---|---|---|
| 概念图 | 文生图（任选合规模型） | 只作参考，不进产品 |
| 卡图/OG 图 | 文生图 → 人工修 → 定稿 | 1200×1200，WebP，<150 KB |
| 贴图 | 文生图 → Blender 上材质 → 出 glb | 1024²，PBR 三通道 |
| 图标 | **不用 AI**（AI 出的图标不一致），用开源图标集 | MIT/Apache |

每张 AI 资产在 `assets/ATTRIBUTION.md` 记：文件名 / 模型与版本 / 提示词摘要 / 日期 / 人工修改点。

## 4. 执行顺序（视觉一致性优先）

1. **V1 全局 token + 组件**（作品集先行，作为样板）；
2. **V2 图标替换**（四个项目各一轮，只换图标不动布局）；
3. **V3 截图重拍/重渲**（四个项目统一取景，优先用 Blender 出图避免截图不一致）；
4. **V4 项目内微调**（乒乓主菜单背景、返航录阵营色、落幕查涨跌双编码）；
5. **V5 空态/加载态**（有数据依赖的项目才需要）；
6. **V6 AI 资产入库 + 归属记录**。

每轮验收：六档视口 + 对比截图（前后各一张）+ 变更记录一条。
