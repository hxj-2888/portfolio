# 游戏合集（Game Collection）· 执行方案 v2

> 状态：**已按你的口径修订，待确认后执行** · 2026-10-21
> 你的口径：**两个游戏「合集」并列，不做功能合并**；返航录**只改展示名，不动仓库名与网址**。

---

## 0. 一句话

做一个**合集首页**（`game-collection`），里面并排放两个**完全独立**的游戏；合集只提供入口、统一视觉与版本信息，**两个游戏的代码一行不改**（除了给游戏页加一个「返回合集」的轻量入口，可选）。

## 3. 「合集」与「作品集」的关系

- 合集是**作品集的一个子项目**（`projects/game-collection/`），作品集首页只放**一张**「游戏合集」卡片；
- 两个游戏**不再各自占一张作品集卡片**（避免同一内容重复展示）——由你决定：**推荐合集单卡**；如果你更想让两个游戏各自可点，就采用「合集卡 + 两个游戏卡」的折中（在 §10 拍板）。

## 5. 风险与口径（与 v1 相同，结论更新）

### 5.1 同步补丁要「先测量后写」
执行前先跑一个只读扫描脚本：对两个源目录 grep `src="/`、`href="/`、`url(/`、`register(`，把所有根绝对路径与 SW 注册点列出来，再按结果写补丁——**不预先臆造规则**（v1 方案里写的 6 条是估计值）。

### 5.2 联机
合集里点「联机」→ **跳独立站**（`ping-pong-duel.pages.dev` / `space-kill-web.pages.dev`）。合集不承载后端。

### 5.3 体积
乒乓排除 APK 后约 300 KB + 音频；返航录排除附件 PDF 后约 1 MB。合集首页 + 两游戏 < 2 MB。

### 5.4 移动端
乒乓竖屏、返航录横屏（App 锁横屏）。合集页**横竖屏都要能用**，进返航录前提示横屏。

## 6. 验收清单

- [ ] `sync:dry` 无 `未匹配`；`sync` 后 `git status` 只有预期文件；
- [ ] 合集首页本地可开，两卡跳转正确，返回合集可用；
- [ ] 作品集弹窗内打开合集：**无 SW 注册**（Application → Service Workers 为空）、Console 0 error；
- [ ] 六档视口（320/360/390/430/768/1280）：无横向滚动、无裁切；
- [ ] 两个游戏各通玩一局（乒乓人机 1 局、返航录单机 1 局到结算）；
- [ ] 离线时合集降级为静态卡片、不白屏。
