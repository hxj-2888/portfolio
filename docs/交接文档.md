## 〇、给接手的人：四句话

1. **`projects.json` 是唯一真相**。首页卡片与预览弹窗都由 `js/site.js` 从它渲染，
   不要再去 `index.html` 里手写卡片——那是重构前的做法，已经删了。
2. **视觉分三层**：`tokens.css`（变量）→ `components.css`（组件）→ `page.css`（版面）。
   `art.css` 在 2026-11-09 重做时**清空**了（光晕/网格属通用装饰）；改配色只动 `tokens.css`。
3. **游戏是「合集」，不是「合并」**。合集页只做入口，游戏代码零改动；
   联机一律跳各自独立站。不要试图把几个游戏揉进一个引擎。
4. **推之前先跑 `npm run check:docs:all`**。不绿就说明代码改了文档没跟上，`git push` 时的 hook 也会再拦一次。
   规则见 `AGENTS.md` §二（2026-11-06 起强制）。

## 二、作品集是怎么渲染出来的

```
fetch('projects.json')
  → 按 order 排序（band 优先）
  → renderRail()：首屏核对清单的行**从 DOM 里已存在的 .artifact__pane 反查项目**，
       保证「清单说在跑」与「实际能切的产物」不会各写一份而漂移
  → renderCases()：按 layout 分发版式
       versions → 同一项目多形态逐条对账（返航录：2.5D / 3D / 表单）
       split    → 媒体 + 规格表（乒乓）
       data     → 大字读数 + 图（落幕查）
       note     → 紧凑信息块（合集 / 过程资料）
       status=local 的形态**不配链接**（没有可打开的产物，给按钮就是把它画成「可做」）
  → 对账表的「可玩网页游戏」数量由 countsAsGame 实时计算
```

**为什么这么设计**：重构前卡片是手写 HTML，加一个项目要改两处、还容易漏。
现在只改 `projects.json`。2026-11-09 又把「同一张卡片套所有项目」改成
按作品性质选版式——三款完全不同的软件不该长得像同一个 SaaS 模板。

### 面板信息分级（别把长文塞回面板）

| 层级 | 内容 |
|---|---|
| L1 面板 | 标题、一句 lead、该作品性质对应的版式（对账/规格/读数）、主链接 |
| L2 弹窗 | 预览、关键数据、技术要点 |
| L3 详情 | 长文、变更记录、下载 |

## 三、游戏合集

- 合集页 `projects/game-collection/index.html` **手写**，两卡并列，各带「开始游玩 / 独立站 / 规则与资料」。
- 两个游戏由 `sync.json` 的 `game-collection` 段白名单搬进 `games/`（109 个文件，**0 个 APK**）。
- **iframe 内不注册 Service Worker**：合集页头部有 `window.__ARCADE_SW__` 标记，
  `sync-projects.js` 每次同步探测它（不命中仅告警，不阻断）。
- 联机跳独立站：`ping-pong-duel.pages.dev` / `space-kill-web.pages.dev`。

### 补丁机制（复用 delta-force 那套，别新造）

`sync.json` 的 `patches` 支持 `regex` / `string` 两种规则，配 `okIfContains` 做幂等。
**新增补丁前先跑 `sync:dry` 看「未匹配」告警**，不要凭猜写规则。

⚠ **`game-collection` 段是一条派生链**：它把两个游戏搬进 `games/`。任一源缺失
（例如太空杀重做期间）整段会失败退出，**排在后面的补丁都不会执行**。所以合集内嵌
副本的适配另有一份独立实现 `tools/fix-embedded-games.cjs`（幂等、只读已入库产物），
`npm run sync` 与 `tools/verify-sync.cjs` 都会调用它。改适配规则时**两处都要改**。

## 四、正文 ↔ 代码同步（返航录）

### 链条

```
权威 PDF（attachment-site/规则正文/）
  → 抽取 md（docs/_返航录v1preview1.0_提取.txt，gitignore）
  → build_site.py → site/rules.html
  → 站点部署

rules-map.json（条款 260 条 + 测试锚点）
  ← gen-rules-map.cjs 从 test-fix-v26.cjs 的**断言名**里提取
```

### 四条校验（`check-rules-sync.cjs`）

| 项 | 查什么 | 失败意味着 |
|---|---|---|
| A | 正文条款 ⊆ 已登记条款 | 新增条款没登记，跑 `npm run rules:map` |
| B | 锚点指向的测试文件真实存在 | 锚点悬空，测试文件被改名/移动 |
| C | PDF / md 的 sha256 与登记一致 | 原件换了但没重登记 |
| D | 站点 rules.html 覆盖 ≥95% 条款 | 正文更新了但站点没重建 |

### 当前读数（2026-11-06 复跑）

```
条款 260 · 已覆盖 102 · 覆盖率 39% · 锚点 274（其中 234 条当前悬空，见下）
```

> ⚠ **234 条锚点悬空是环境造成的，不是新增债**：锚点指向
> `../太空杀游戏-完整版/tools/test-fix-v26.cjs`，该目录已被删除/改名。
> 恢复源目录后重跑 `npm run check:rules`，悬空数应回到 0。
> A（正文 md 缺失）与 C（PDF/md 指纹缺失）同理，都因为找不到源仓库。

### ⚠ 两个已知的解析坑（改这两个脚本前必读）

1. **夜间步骤号会被当成条款**：正文 md 里 `#### 0.1 外星人蛰伏…` 是**步骤号**不是 §0 条款。
   过滤必须按**标题形态**（长度 >24 / 以标点开头 / 含动作词），
   **不能按编号白名单**——`0.5 裁判次序`、`0.6 术语统一` 既是步骤号也是真条款，按编号会误杀。
2. **`\s` 会跨行匹配**：`#### 3.3.10` 后面那行正文会被当成标题。
   分隔符必须用 `[ \t]`、标题类用 `[^\r\n]`。
   gen 与 check **必须用同一套过滤**，否则会出现「正文 259 / 登记 260」的假差异。

### ⚠ 附件站曾经没有 CI

2026-10-21 之前 `space-kill` 靠手动 `wrangler pages deploy`，**已因此漏发过三份规则 PDF**
（线上返回 `text/html` 的 SPA 回退，而仓库里文件齐全）。

现在 `deploy.yml` 里有两条保护：

- 部署前：重建 `site/` 与提交版 `diff -r`，不一致即失败；
- 部署后：**四份 PDF 必须 `application/pdf` + 首字节 `%PDF`**（只看 HTTP 200 会被 SPA 回退骗过去）。

### 推送注意

- 两个仓库都有 `origin`(GitHub) 与 `gitee` 两个远端，**都要推**。
- **CI 会在你推送间隙往 `portfolio` 提交**（`sync-attachment-site` 工作流）。
  推前先 `git fetch origin`，发现分叉就 **`git rebase`**（不是 merge），
  rebase 后 Gitee 需 `--force`（那里只有自己的旧副本才可强推）。

## 六、设计约定（改样式前先看）

> **2026-11-09 重做**（redesign/frontend-design 分支，依据 Anthropic `frontend-design` skill）：
> 中性冷灰底 `--paper:#F2F4F7` + 蓝黑 `--ink:#10161E`；唯一 UI 强调仍是深琥珀 `#8A5A00`
> （保留 2026-10-25 的对比度推导结论）。版式改为「工作台首屏（核对清单 + 正在运行的产物）
> → 对账表 → 作品面板（按性质分版式）→ 规则与过程 → 做法 → 联系」。
> 旧版的暖色晕 / 网格纹理 / 统一圆角卡片 / ALL-CAPS 小标签 / 单词斜体强调 / 01-02-03 编号
> 全部移除——它们与主题无关，是生成页的通用胎记。

1. **色彩只属于作品**：全局只有中性底 + 一个 UI 强调琥珀 + 一个语义绿 `--verified`（只表示在线/已核对）。
   三个作品色（乒乓青、返航录蓝、落幕查橙）只在该作品自己的面板与清单行内出现，靠 `.hue-*` 类注入。
2. **不用图标**：2026-11-09 起移除手绘 inline SVG 图标层（AGENTS §2.8：缺署名素材不上站，自绘图标无来源）。
   文字链接本身已足够清楚。也不引 emoji 当图标。
3. **不引 CDN / 不引字体**：站点自称「0 外部依赖运行时」，中文性格靠字重/字号/字距，不下载新字体。
4. **媒体按作品性质给**：有实机录屏的用录屏（静音循环），只有界面的用截图；无图条目不留空图区。
5. **首屏可验证**：首页每个数字都必须能点开验证，不许出现评分/年限/行业数这类无来源数据（`check-copy.cjs` 会拦）。
   等宽字体只承载可核对字符串（版本/指纹/对账数），不做装饰性小标签。
6. **CSP 分两层**：根 `_headers` 严格（`script-src 'self'`、`style-src 'self'`），`projects/_headers` 对内嵌副本放宽 `'unsafe-inline'`（游戏副本仍有内联脚本）。改完跑 `npm run check:headers`。首页因此**不写内联 style**。
7. **动效统一受 `prefers-reduced-motion` 控制**；全站只保留首屏一次编排，不做逐卡片淡入。
8. **分享图**：`assets/og.png` 为 1200×630 标准比例，改动标题文案后需要重做。
