## 现象 / 需求

1. 把「乒乓对决」与「返航录」两个网页游戏合成为**一个游戏包**，接入作品集展示；
2. 个人网页设计待优化（本轮**只要方案**）；
3. 拓展 AI 相关技术：**AI 借游戏引擎开发**、**AI 接入 Blender 建模**、**AI 协助创作美术素材**；
4. 开工前先从开源社区（GitHub）取经，并**给项目留痕**：Markdown 里留下版本变更。

## 根因 / 决策

- **游戏包形态**：大厅 + 两个各自独立的子包（用户确认）。理由见 `docs/GAME-ARCADE-方案.md` §4.1——乒乓有「引擎 7 对字节一致」红线、返航录有「唯一裁剪出口」红线，物理合并会同时踩两条。
- **同步机制**：复用已有的 `sync.json` + `sync-projects.js`（白名单 + 补丁 + neverCopy + dry-run），不引入第三方门户框架。
- **开源取经结论**：游戏包不需要外部参考，你自己两轮踩坑固化的机制就是最优解；AI 侧的价值点在「MCP + 本地 bpy 脚本」和「离线生成→静态资源入库」两条，详见 `docs/开源调研.md`。
- **AI 示例选型**：选**乒乓台**（ITTF 尺寸确定、与游戏能对上、无需外部素材），用 `blender --background --python` 跑脚本，产物字节级可复现。

## 已否决

- **物理合并两个游戏**：会破坏乒乓 7 对引擎镜像与返航录唯一裁剪出口，成本远大于收益。
- **引入第三方门户/框架做大厅**：增加 SW 与 CSP 边界，收益不抵风险。
- **线上运行时调用生成式 API 出美术**：作品集 CSP 目前只允许 `'self'`，且会让页面质量受外部服务波动影响。
