## 一、现象/需求

1. **静态图看不出「这游戏能玩」**：首屏展示台与作品卡都是截图，访客无法判断是否真有玩法。
2. **内嵌预览白屏**：`sync.json` 的 ping-pong 白名单缺 `js/app/home.js` 与 `js/app/icons.js`，而 `index.html` 会加载它们——内嵌副本里这两个请求 404，主页交互脚本缺失。
3. **`verify-sync` 假报**：第 3 步「逐字节比对」没有归一化换行符，Windows 上 `core.autocrlf=true` 时入库 blob 是 LF、工作区是 CRLF，同一份内容被判成「落后于源仓库」。

## 二、根因/决策

| 项 | 决策 |
|---|---|
| 静态图 | 换**真实对局**静音循环视频（两个 AI 看台侧视角对打），不做剪辑拼接，避免「看着像宣传片不像实机」 |
| 视频多份成本 | 首屏展示台与卡片用**两个不同时长的版本**（24.3s 完整过程 / 18.9s 从进对局起截），并用 `IntersectionObserver` 进视口才播、离开即停，不为屏外内容付解码成本 |
| 首屏抢开局 | 首屏默认停在「返航录」，点「乒乓对决」标签才播放；切走暂停并归零；页面隐藏时暂停 |
| 白名单缺口 | 补白名单后重新同步，两个副本与源 `public/` 逐文件对齐 |
| 假报 | `verify-sync.cjs` 加 CRLF→LF 归一，与 `deploy.yml` 的 `tr -d '\r'` 口径一致 |

> **源视频生成方式**：游戏仓 `npm run record:demo`（`tools/record-demo.cjs`），用 CDP `Page.startScreencast` 抓整页帧（canvas + 比分 HUD 一起入镜）。
> **不要用 `canvas.captureStream`**——那样 HUD 全部缺席。
