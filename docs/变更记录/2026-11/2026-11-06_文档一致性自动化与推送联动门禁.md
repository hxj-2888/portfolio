# 2026-11-06 文档一致性自动化与推送联动门禁

> 现场记录。承接同日《文档偏移治理与推送同步门禁》，把「靠人记得跑」升级成「机器自动拦」。

## 一、现象/需求

上一轮治理后，门禁只回答了「有没有写文档」：拿最新记录日期和最近提交日期比。
但另一类偏移它一条都抓不到——**文档写了、日期也对，里面的数字却是错的**：
本仓曾写 6 条项目 / collect 6/6（实际 7 / 7/7），实盘终端曾写测试 44/46 项（实际 53/63）、
TTL 10/15/10/30s（实际 60/120/60/120s）、刷新 60s（实际 180s），
还有 `/api/history/mix` 在文档里挂了一个多月、代码里根本没有这个路由。

此外 `npm run check:docs` 只在本机手动跑，既没接 CI，也没在 `git push` 时强制触发。
需求：要一套能**自动检测新内容与推送文档是否一致**的流程。

## 二、根因/决策

根因是校验维度单一：日期只是「有没有写」的代理指标，既不是「写得对不对」的证据，
也不是「这次推送带没带文档」的证据。

决策：分三层，各管一件事，不互相替代。

| 层 | 回答的问题 | 落地 |
|---|---|---|
| 事实契约 | 文档里的数字 / 索引 / 读数 == 代码事实吗 | `tools/doc-facts.mjs` + `tools/check-doc-facts.mjs` |
| 推送联动 | 本次提交改了实质文件，带记录和索引了吗 | `tools/check-push-docs.cjs` |
| 新鲜度（已有） | 记录日期 / 索引指向 / 交接 HEAD 跟得上吗 | `tools/check-docs-fresh.cjs` |

被否决的方案：

- **把日期门禁直接接 CI**：`sync(space-kill)` 机器人提交会不断推后「最近提交日期」，
  连续几次就误红并卡住部署。改为按 commit range 逐提交归类，机器人提交天然放行；
  `check-docs-fresh.cjs` 的 HEAD 落后计数也改成只数人类提交。
- **靠定时巡检**：只能事后发现，拦不住推送。要的是事件驱动（pre-push hook + CI）。
- **三类校验塞进一个脚本**：报错互相掩盖，且 hook 需毫秒级、CI 才跑得起实跑命令。
  于是 `--full` 只给 CI 用，本地 hook 只跑静态事实。
- **契约写成 JSON**：正则双重转义极易错（首版就踩了 `**` 被当量词）。改用 JS 模块写正则字面量。

触发点三处：本地 `pre-push`（含 Gitee 推送）、GitHub Actions `docs-gate.yml`、手动 `npm run check:docs:all`。

## 三、改动（文件级）

新增：

| 文件 | 作用 |
|---|---|
| `tools/check-doc-facts.mjs` | 通用引擎：单点事实（jsonPath / countLines / capture / countInCapture / command）+ 集合事实双向差集；`--full` 才跑命令类 |
| `tools/doc-facts.mjs` | 本仓契约：7 项静态事实 + 1 项实跑 `collect`，1 组「索引表 ↔ 实际记录文件」集合 |
| `tools/check-push-docs.cjs` | diff 驱动门禁：解析 commit range，逐提交区分人类/机器人，判「实质改动 ↔ 新记录 ↔ 索引刷新」 |
| `.githooks/pre-push` | 串联三道门禁，`set -e` 不绿不许推 |
| `.github/workflows/docs-gate.yml` | 独立 CI workflow（push / PR / 手动），**不改动 deploy.yml** |

修改：

- `tools/check-docs-fresh.cjs`：① HEAD 落后只数人类提交；② 同一天多条记录按文件 mtime 定「最新一篇」，不再靠文件名字典序碰运气
- `package.json`：新增 `check:facts` / `check:push` / `check:docs:all` / `check:docs:full`，`prepush` 改为跑全套 + `check-copy`
- 本地 git 配置 `core.hooksPath = .githooks`（非文件，用 `git config --get core.hooksPath` 可查）
- 本记录、`修改记录.md`、`docs/变更记录/README.md`、`docs/README.md`、`docs/交接文档.md`、`AGENTS.md`

## 四、验证

```text
node tools/check-doc-facts.mjs
  → EXIT=0；7 项单点事实全绿；changelog.index 10 项双向一致
node tools/check-doc-facts.mjs --full
  → EXIT=0；collect 实跑「✅ 成功: 7」= docs/README「应 7/7」
node tools/check-push-docs.cjs
  → EXIT=0；范围 7d88f48..HEAD，0 个待推送提交
node tools/check-push-docs.cjs --base cf54340 --head 7d88f48   （负向：历史断更区间）
  → EXIT=1；「6 个提交（机器人 1），33 个实质文件，却没有新增变更记录」
node tools/check-push-docs.cjs --base ed6cbff^ --head ed6cbff  （负向：纯机器人提交）
  → EXIT=0；「本次 1 个提交全为 CI 机器人提交，按 AGENTS.md §2.5 放行」
printf 'refs/heads/main <sha> refs/heads/main <sha>\n' | sh .githooks/pre-push
  → HOOK_EXIT=0
git config --get core.hooksPath   → .githooks
node tools/check-docs-fresh.cjs   → EXIT=0；HEAD 落后 0 个人类提交
```

YAML 静态检查：`on:` / `jobs:` 均在，67 行。

## 五、未做/遗留

- `docs-gate.yml` 是**独立 workflow，不阻塞部署**。要「不绿不许上线」，需到 GitHub 分支保护里把 `docs` job 设为必需检查；本次没动仓库设置。
- 只覆盖 GitHub；Gitee 推送靠本地 pre-push hook，Gitee 侧没有 CI 校验。
- 事实契约只登记当前易漂移的 8 项。`sync:dry` 的 2/2/1 是**环境性红**（源目录缺失），刻意不纳入契约，否则换台机器就误伤。
- 命令类事实 `collect.success` 设了 `onError: 'warn'`：CI 少源目录时只警告，不硬失败。
- CI 的 `--full` 会实跑 `build-collect.js`；若它将来改为依赖外部源仓库，需要同步调整该项。
- 同一天写多篇记录时，`修改记录.md` 的 LATEST 指向「最后写入的那篇」；不要手工把两条同日记录的顺序当事实。
