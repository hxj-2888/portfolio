# 2026-11-06 推送门禁「首次推送」兜底 + 索引排除规则修正

> 现场记录。起因是把同一套门禁复用到刚纳入 git 的「实盘终端」仓，顺带修掉本仓一个潜在隐患。
> 相关：[文档一致性自动化与推送联动门禁](./2026-11-06_文档一致性自动化与推送联动门禁.md)。

## 一、现象/需求

用户要求「做和其他项目一致的工程化处理」，需要把 `tools/check-push-docs.cjs`
复制到实盘终端复用。复制前复核发现三个问题：

1. **首次推送是检查盲区**：脚本在没有 upstream、`HEAD^` 也不存在时（新仓库恰好如此），
   直接 `warn(...) → process.exit(0)` 跳过联动检查。也就是说**新仓第一次推送完全不设防**。
2. **warning 文案硬编码本仓路径**：「请同步 docs/README.md 与 交接文档.md」在别的项目里
   指向不存在的文件，会误导。
3. **本仓 `.gitignore` 把 `修改记录.md` 列为「本机工作笔记」排除**，但该文件早已 tracked，
   且是 `check-docs-fresh.cjs` 校验 LATEST 区块的**唯一输入**。当前没出事只是因为 tracked
   文件不受 ignore 影响；一旦有人 `git rm --cached` 或在新克隆上重建，索引会消失、门禁失效。

## 二、根因/决策

1. **不跳过，改为 root 范围**。新增 `ROOT_ONLY` 分支：无法确定 base 时把 range 设为 `HEAD`，
   `git log --name-only HEAD` 列出 HEAD 可达的全部提交；对首次推送等价于「检查整个历史」，
   仍要求有新增记录 + 索引刷新。portfolio 有 upstream，走原路径，行为不变。
   否决「拿空树 SHA 当 base」：需要额外构造 `git hash-object -t tree /dev/null`，
   在 CI 的 shallow clone 里更脆。
2. **文案通用化**：改成「请同步 README.md / AGENTS.md 与主文档对应小节」，两仓都成立。
3. **`.gitignore` 只改注释、不动其他规则**：把排除行换成「必须入库」的说明，并注明
   「勿再加回」。没有删除任何仍生效的排除项。
4. **按 AGENTS.md §二 补一篇记录并刷索引**：本次改了 `tools/*.cjs` 与 `.gitignore`
   两个实质文件，不写记录的话 `check-push-docs` 会在下次推送时把本仓自己拦下来。

## 三、改动（文件级）

| 文件 | 改动 |
|---|---|
| `tools/check-push-docs.cjs` | 新增 `ROOT_ONLY` 分支与 `range` 变量；`rangeOK` 在 root 模式只校验 head；范围输出显示 `(root)`；阅读文件 warning 通用化 |
| `.gitignore` | 删除 `修改记录.md` 排除行，改为「必须入库」的注释与警示 |
| `修改记录.md` | LATEST 与「最近变更」表刷新为本文 |
| `docs/变更记录/README.md` | 索引表加一行（否则 `check-doc-facts` 的 `changelog.index` 集合比对会红） |
| `AGENTS.md` | §2.7 补一条「首次推送不再是盲区」的门禁口径说明 |
| 实盘终端 `tools/check-push-docs.cjs` | 复制同源版本（该仓的改动记在它自己的 11-06 记录里） |

## 四、验证

```bash
node tools/check-push-docs.cjs --quiet                    # EXIT=0（常规路径不变）
node tools/check-push-docs.cjs --base cf54340 --head 7d88f48   # EXIT=1，断更区间仍被拦
node tools/check-push-docs.cjs --base ed6cbff^ --head ed6cbff   # EXIT=0，机器人提交仍放行
git check-ignore -v 修改记录.md                          # 无输出（不再被忽略）
git ls-files 修改记录.md                                 # 有输出（已 tracked）
node tools/check-doc-facts.mjs                           # EXIT=0，索引表与实际记录一一对应
node tools/check-docs-fresh.cjs                          # EXIT=0，LATEST 指向本篇
```

实盘终端侧的首次推送分支由该仓记录里的验证段覆盖。

## 五、未做/遗留

1. 本仓的 `docs-gate.yml` 未改：它的 base 来自 `github.event.before` / PR base，
   首次推送时 workflow 内 `git rev-parse HEAD^` 仍可能为空字符串，此时 `--base ""`
   会让脚本自己走 `ROOT_ONLY` 兜底，行为正确，无需改 workflow。
2. 分支保护仍未设为必需检查（仓库设置，非代码）。
3. 实盘终端远端尚未创建；其 `origin` / `gitee` 由用户建仓后配置。
