# 2026-11-13 首页返航录 2.5D / 3D 分列 + 3D Demo 档位放大

> 现场记录。本批只改首页渲染器与样式（`js/site.js` / `css/page.css`）与文档；
> **不改 `projects.json`、不改内联数据、不改合集页、不改 3D 数据**。
> 需要重新部署才生效。

## 一、现象/需求

- 用户指出：首页 returnlog 的 3D 槽位太小（浅槽）；2.5D / 3D 应当和落幕查
  同等级的项目，给予充分的空间。
- 现状：returnlog 用 `versions` 紧凑表格渲染；2.5D / 3D 只是表格行，
  3D 是一条虚线行，空间远小于落幕查的整宽媒体区。

## 二、根因/决策

| 项 | 决策 |
|---|---|
| 2.5D 分列 | 渲染器把 returnlog 的 versions 拆成两条独立 `.item`：**新返航录 · 2.5D** 用整宽实机视频 + 260/274/10,000 规格 + 打开/扫码 + GitHub/Gitee/APK |
| 3D 分列 | **新返航录 · 3D** 独立一条：整宽虚线 Demo 槽位，与 2.5D 视频同宽（1440 高约 500 / 390 高 320）；显示 3D 的真实 proof 与描述，不伪造视频/链接 |
| 过渡式表单 | 作为 2.5D 项末尾的「在合集里打开」一行，不再单独占版本行 |
| 数据 | 不新增项目；仍读 `projects.json` 的 `returnlog.versions`；项目数 7 不变，3D 数据不动 |
| 窄屏 | 3D 槽位最初用 `aspect-ratio + min-height`，在 390 下反推了 512px 最小宽度（CDP 实测 layout viewport 528）；改为 `width:100% + min-height:clamp(320px,40vw,500px)`，390/320 恢复无溢出 |
| 已否决 | 新增 2.5D/3D 项目条目（会改 projects.length / collect / 事实契约）；伪造 3D 视频；把 2.5D 独立站 iframe 进首页 |
