## 一、现象/需求

- 2026-11-06 的门禁改动仍散在工作树：`AGENTS.md`、`.githooks/pre-push`、
  `.github/workflows/docs-gate.yml`、三个 `check-*` 脚本、6 篇补记与 2 张 WebP 未提交；
  `docs/交接文档.md` 仍写「本次文档治理的改动尚未提交」。
- 文档索引存在过期副本：`space-kill-3.0/README.md` 是已退役嵌套克隆的旧 README
  （remote 404），但它属于同步源目录，不能按普通文档删除。
- 需要把「门禁 + 入口文档 + 索引 + 记录」作为一个可复现的提交收口，避免新克隆上
  `check:docs` 没有输入、或索引指向不存在的记录。

## 二、根因/决策

| 项 | 决策 |
|---|---|
| 门禁入库 | 三道门禁（新鲜度 / 事实契约 / 推送联动）与 `package.json` 脚本、pre-push hook、CI workflow 同批入库；否则门禁只在当前工作树有效 |
| 交接文档 | 头部日期推进到 2026-11-08，工作树改为「除本地诊断脚本外干净」；`HEAD` 保留 `7d88f48`（自指提交无法写入自身哈希，门禁允许落后 ≤2） |
| 过期 README | 本仓不保留重复的入口 README；`space-kill-3.0/README.md` 保留在忽略目录中，待该同步源正式退役时再随目录处理 |
| CI 强度 | `docs-gate.yml` 先作为独立状态检查，不设为部署必需检查；避免文档门禁卡住线上发布 |
| 配图 | `returnlog.webp` / `returnlog-640.webp` 随 `js/site.js` 的 `srcset` 一起入库，避免线上 404 |
