# 2026-11-09 APK 出口更新与《返航录》重复计数合并

> 现场记录。起因是「把三端 APK 更新到作品集」，核对出口时发现作品集里三处过期/失效引用，
> 并牵出一个更早的计数错误：旧《返航录》与新《返航录》是同一个项目，却被算成两款可玩游戏。
> **本轮改了站点代码与产物副本**（`projects.json` / `index.html` / 两个内嵌副本 / `sync.json`），需要重新部署。
> 前序记录：[2026-11-08 文档门禁收口](./2026-11-08_文档门禁收口与过期副本清理.md) ·
> [2026-11-01 新返航录接替首屏](./2026-11-01_新返航录接替首屏.md)。

## 一、现象/需求

1. **APK 出口要跟上**：源仓库 `乒乓对决_合并`（3.6.0，11-07 还有 HUD/按键改动）与
   `delta-force-deploy`（bundle `v20261025q`，11-08 文档校准）都已前进，作品集副本停在 10-28 / 10-24。
2. **落幕查副本落后一个 bundle 版本**：作品集内 `projects/delta-force/index.html` 是
   `build: v20261024w-de573b74`，源已是 `v20261025q-8e307264`。
3. **乒乓独立副本的 APK 按钮是坏的**：`projects/ping-pong-duel/index.html` 第 156/157 行
   `href="PingPongDuel-v360.apk"`、`href="download"` 仍是相对路径。`js/app/main.js` 在
   `PPD.isTouch && location.protocol !== 'file:'` 时会显示该按钮，所以**手机在作品集域名下点它
   会下到一个改名成 `.apk` 的网页**——正是 `sync.json` 注释里写明的那个成因。
4. **QR 标题停在 v3.2.1**：`projects.json` 乒乓卡片写「乒乓对决 v3.2.1」，实际 3.6.0。
5. **旧《返航录》的 APK 出口已死**：`assets/qr/space-kill-apk.png` 指向
   `https://space-kill(-web).pages.dev/SpaceKill.apk`，实测两个域名都返回 **200 + `text/html`**
   （SPA 回退，不是 APK）。
6. **《返航录》被重复计数**：`countsAsGame` 为 3（乒乓、新返航录、旧返航录），但首屏
   `index.html` 的手写兜底是 `data-count="games">2`，`game-collection` 卡片也叫
   「游戏合集 · 两个游戏」——运行时值一直在覆盖那个 2，说明重复计数是后来漏进来的。

## 二、APK 出口实测（本轮判断依据）

用 Range 请求取首 4 字节判 ZIP 魔数（`50 4B 03 04`），避免被「200 但其实是 HTML」骗过去：

| 出口 | 结果 |
|---|---|
| `ping-pong-duel.pages.dev/PingPongDuel-v360.apk` | ✅ 200，`application/vnd.android.package-archive`，ZIP 魔数，3,982,743 B |
| `ping-pong-duel.pages.dev/PingPongDuel-v361.apk` | ❌ 200 但 `text/html`，魔数 `3C 21 44 4F`（`<!DO`），46,338 B → **不存在**，回退页 |
| `delta-force-v5.pages.dev/delta-force.apk` | ✅ 200，ZIP 魔数，28,984 B（WebView 壳，`MainActivity.java:48` 加载线上站点，内容更新不需重打包） |
| `delta-force-v5.pages.dev/download.html` | ✅ 200，HTML 页面本身（正常） |
| `github.com/hxj-2888/returnlog/.../ReturnLog.apk` | ✅ 206，ZIP 魔数，45,592,187 B |
| `space-kill.pages.dev/SpaceKill.apk` | ❌ 200 + `text/html` → 死链 |
| `space-kill-web.pages.dev/SpaceKill.apk` | ❌ 200 + `text/html` → 死链 |

另外两条影响判断的实测：

- **线上乒乓 `js/render.js` 指纹 = `9d98dfa57b57`**，与本地源仓库归一化换行后同值 →
  11-07 的改动**已在线上**，作品集该跟上的是同一份。
- **线上 v360 与本地 v360 同尺寸、不同 SHA256**（`6B2B35FD…` vs 本地 `83C26435…`），
  且 11-07 那次 run 的 `Build APK: success` → CI 重建了包**但没换文件名**（版本仍是 3.6.0）。
  老用户无法靠文件名分辨新旧，本轮未处理，记在 §五。

## 三、根因/决策

| 项 | 根因 | 决策 |
|---|---|---|
| 乒乓 index.html 坏链 | `sync.json` 的 `ping-pong-duel` 段只给 `download.html` 配了补丁，`index.html` 从未适配；合集段反倒同时适配两个文件 | 给独立副本补上同款 `index.html` 补丁（3 条规则），两份副本口径一致 |
| 合集乒乓副本没跟上 | `sync-projects.js` 的 `expandFileEntries` 在**拷贝之前**就因 `../太空杀游戏-完整版` 缺失整段抛出，排在前面的乒乓分组一个文件都没搬；而 `deploy.yml` 的 Cross-check 要求两份副本同源，只更新独立副本会让 CI 红 | 按 `sync.json` 乒乓分组白名单**单独搬运一次**（复用同步器同款 glob/neverCopy 规则，预期 43 / 更新 9），再跑现成的 `tools/fix-embedded-games.cjs` 适配。不新建工具脚本、不改 `sync.json` 的失败语义 |
| 不改为补齐 `太空杀游戏-完整版` | 该仓已改名 `returnlog`，克隆回来拿到的是**新返航录**而非旧太空杀产物，会污染 `games/space-kill/`；`sync-attachment.yml` 还特意把附件站源钉在 SKV3 重写前的提交 | 维持「环境性红」判定，不动 CI 的克隆地址与钉定 |
| 旧《返航录》卡片 | 它与新返航录同一项目，`liveUrl` 现在也指向新返航录；`space-kill.pages.dev` 实测标题「新返航录 · 星途归航 — 任务档案终端」 | **删掉 play 组卡片**，把规则资料接进 process 组「规则正文与资料」。预览路径由 `js/site.js:216` 的 `'projects/' + p.id + '/' + p.entry` 推导，故该卡 `id` 改为 `space-kill` 并补 `entry`+`source`，让 CI 持续同步的 `projects/space-kill/` 不再成孤儿 |
| `returnlog` 仓库地址 | 仓已改名，`space-kill-web` 靠 GitHub/Gitee 重定向侥幸可用（实测两个域名的 APK 都 206 同尺寸） | 作品集侧一律改规范名 `returnlog`，不再依赖重定向 |
| `SpaceKill.apk` 死链 | 游戏站域名被新返航录接管，二进制不在 | 用户裁定：**移除该卡片的扫码入口**（不替换成新返航录的包，避免给旧游戏卡片挂别的安装包） |

## 六、未做 / 遗留 / 已否决

- **未做：CI 的克隆地址仍是旧仓名**。`deploy.yml:81` 与 `sync-attachment.yml:48` 用
  `hxj-2888/space-kill-web` 克隆，靠重定向可用。属部署基础设施且附件站源特意钉了提交，
  未擅自动；要改请单独一轮并验证钉定语义。
- **未做：乒乓 APK 文件名未随内容递增**。版本仍 3.6.0，CI 11-07 重建了包但发布名照旧
  `PingPongDuel-v360.apk`（线上 SHA256 与本地 10-28 包不同、尺寸相同）。老用户与新用户
  拿到的是同一个 URL，无法分辨。修法在源仓（bump 版本或让 CI 校内容哈希），不在作品集。
- **未做：两个资源已成孤儿但未删**——`assets/projects/space-kill.png` 与
  `assets/qr/space-kill-apk.png`（后者仅被 `games/space-kill/js/ui.js` 这个同步产物字符串命中）。
  删除是不可逆动作，留待确认。
- **未做：本轮未提交、未推送**。工作树另有他人遗留的未跟踪文件
  `tools/workbuddy-connect-doctor.cjs`，提交时按文件点名 add，不用 `git add -A`。
- **环境性红（非本轮引入）**：`check-rules-sync` 报 A/C/D 三项失败、234 条锚点悬空，
  根因是本地 `../太空杀游戏-完整版` 已删除/改名。见 `docs/交接文档.md` §九，
  **不要为让它变绿去改 `rules-map.json`**。
- **已否决：为跑通本地合集同步而克隆 `returnlog` 顶替 `太空杀游戏-完整版`**——拿到的会是
  新返航录内容，把旧太空杀产物覆盖掉，比环境性红更糟。
- **已否决：把 `SpaceKill.apk` 的扫码入口改指向 `ReturnLog.apk`**——给旧游戏卡片挂另一款
  安装包会误导玩家；用户裁定移除入口。
