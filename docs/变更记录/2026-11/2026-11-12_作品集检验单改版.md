## 一、现象/需求

- 用户反馈：线上 `https://portfolio-ji.pages.dev/` 的「作品」区整块空白，
  页面上留着一行「项目数据加载失败，请刷新重试。」；换多个浏览器都一样。
- 排查：页面 HTML/CSS/JS 都能加载，失败的是 `fetch('projects.json')`。
  从本机对 `portfolio-ji.pages.dev` 连测 10 次，**2 次直接超时、1 次只收到
  8,712 / 11,650 字节就中断**；另一次 `curl` 收到 1,478 字节后卡死。
  未知路径还会被 Pages 回退成 `index.html`（200 text/html），`r.json()` 解析失败
  同样落到 catch 分支——这两类失败在用户侧表现一致，都是「作品整块消失」。
- 用户同时要求：按 Anthropic `frontend-design` skill 重做页面；
  不要让色块导致文字看不清；留一个 3D 槽位（另一条工作流在接入 3D 版）。

## 二、根因/决策

| 项 | 决策 |
|---|---|
| 作品区消失 | 根因是**渲染依赖第二次网络请求**。改为构建时把 `projects.json` 内联进 `index.html` 的 `#projects-data`，页面只依赖 HTML 本身；`fetch` 只作为内联块缺失时的兜底，并带一次重试。`tools/inline-projects.cjs` 负责生成，`check:inline` 拦住漂移 |
| 设计方向 | 按 skill 的「先定 token 计划 → 对照 brief 自查 → 写码 → 截图自审」流程，选「检验单」：整页是一张可核对的验收单，左侧 220px 版心边栏，右侧主张 + 样张；作品区逐行检验项 |
| 色彩/可读性 | 去掉上一版每件作品一块颜色。只保留纸 `#F3F5F6`、墨 `#0F1418`、验收朱红 `#A33A2A`、在线松绿 `#0B5C40`；正文 16.94:1、次要文字 7.20:1、朱红 6.01:1、松绿 7.33:1（WCAG 2.1 实算），白字只出现在朱红按钮上（6.57:1） |
| 字体 | 宋体只承担大标题/作品名，黑体承担正文与控件，等宽只给真数据串；不用 ALL-CAPS 小标签、单词斜体强调、中间点元信息串 |
| 3D 槽位 | 不新增假数据、不动另一条工作流的 3D 条目。渲染器把 `versions[].status=local` 映射为虚线「待接入」槽位；对方改成 `live` 并补 `url` 即自动变成普通形态行 |
| CSP | 旧版根 `_headers` 写两行同名 CSP，指望浏览器执行更宽松那条；实测 Pages 把同名头合并成一条逗号分隔策略，按 CSP 规范是**取交集**，严格策略始终生效，`/projects/*` 的内联脚本/样式全被拦。改为根 `/*` 单条严格策略；`/projects/*` 先用 `! Content-Security-Policy` 删除继承的严格策略，再设宽松策略 |
| 已否决 | ① 只加重试：首次访问仍可能整块空白，且 Pages 的 SPA 回退会返回 HTML 200；② 全站放宽 `'unsafe-inline'`：能用 `!` 按路径隔离，就不扩大首页攻击面；③ 给 3D 槽位编造版本号或链接：槽位只陈述「暂无网页产物」 |
