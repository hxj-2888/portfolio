## 二、根因/决策

| 项 | 决策 |
|---|---|
| 补记 15 个提交 | 按日/主题拆成 **6 条**记录（10-24、10-25×2、10-28、11-01、11-06），依据 `git show` 的提交正文与 diff 回填，每条开头声明「补记」并列出回填依据的提交号 |
| 只写规定不够 | 同步做 `tools/check-docs-fresh.cjs`，把「改了代码不写记录」变成 `exit 1`，否则下次还会断 |
| HEAD 自指问题 | 文档里的 HEAD 永远比写入时落后 1~2 个提交（写文档本身产生提交）。校验改为「是当前 HEAD 的祖先且落后 ≤ 2」，不做严格相等 |
| CI 自动提交 | `sync(space-kill):` 这类工作流提交不要求写记录，校验按 `sync(` 前缀 + `github-actions` 作者放行；人工的 `sync:` 前缀仍要求记录（两者靠括号区分） |
| 红门禁要写清楚 | `check-rules-sync` A/C/D 与 `sync:dry` 的 `game-collection` 段失败，根因是本地 `../太空杀游戏-完整版` 已删除/改名。这是**环境缺失**，不是代码回归，必须在文档里标注清楚，否则接手的人会去改 `rules-map.json` 试图变绿 |
| returnlog 的 WebP | 用 ffmpeg 按**原生 960 宽**生成，不做向上采样（不伪造分辨率）；`1200w` 描述符与真实宽度的偏差记入遗留，等重截 1200×750 再消掉 |

### `check-docs-fresh.cjs` 的四项校验

| # | 查什么 | 失败意味着 |
|---|---|---|
| 1 | `docs/变更记录/` 最新一篇日期 ≥ 最近一次人类提交日期 | 改了代码没写记录 |
| 2 | `修改记录.md` 的 LATEST 区块指向的就是那一篇 | 索引没刷新，或指向了旧文件 |
| 3 | `docs/交接文档.md` 的 HEAD 是当前 HEAD 祖先且落后 ≤ 2 | 交接文档没跟上结构/读数变化 |
| 4 | 记录文件名与内部日期一致（`YYYY-MM-DD_主题.md`） | 命名不规范，索引会错位 |

## 五、未做/遗留

- **`check:docs` 没有接进 CI**，只在 `npm run prepush` 里。原因是 CI 的 `sync(` 自动提交会不断把「最近提交日期」推后，硬接会让部署被文档卡住。要不要接，需要先决定机器人提交的口径。
- `returnlog.png` 仍是 960×540，需按原生分辨率重截并重制到 1200×750；在那之前 `srcset` 的 `1200w` 描述符偏高约 20%。
- 五篇补记**是事后回填**，与当时的现场记录不等价：提交正文里没写的取舍（例如某次改动为什么选 A 不选 B）无法还原，只能留白。
- `docs/data/shot-*.png`（7 张约 4.3 MB）未转 WebP。
- 实盘终端（`realtime-terminal`）的同类治理在其自身仓库的 `修改记录.md` 记，不在本仓重复。
