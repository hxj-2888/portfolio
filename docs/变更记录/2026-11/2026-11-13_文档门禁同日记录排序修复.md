# 2026-11-13 文档新鲜度门禁：同日多记录排序误判修复

> 现场记录。本批只改 `tools/check-docs-fresh.cjs` 与文档；不改站点代码、不改视频。
> 触发原因是 2026-11-13 当天出现多条变更记录，CI 的 docs-gate 误判「最新一篇」。

## 一、现象/需求

- 视频批次提交 `f36dbdf` 的 GitHub `docs-gate` 失败：
  `修改记录.md` 指向 `2026-11-13_作品演示视频批次.md`，但门禁认为最新一篇是
  `2026-11-13_首页返航录2.5D与3D分列.md`。
- 同一工作树本地 `npm run check:docs:all` 通过；只有 CI 失败。

## 二、根因/决策

- `check-docs-fresh.cjs` 对同日记录先按 mtime 排序，mtime 相同再按相对路径字典序。
  本地文件 mtime 有先后；CI checkout 后所有记录 mtime 相同，字典序里「首」>「作」，
  于是把「首页…」当成最新，和「修改记录」指针不一致。
- 同一日期内的记录顺序**本来就不唯一**；门禁真正要守的是：
  1) 最新记录日期 ≥ 最近提交日期；2) `修改记录` 指向一条**日期等于最新日期**的记录；
  3) 索引表与实际文件集合双向一致（`check-facts` 负责）。
- 决策：把指针校验改为「目标记录存在且日期 == 最新日期」；不再要求它等于某一个
  由 mtime/字典序选出的“唯一最新”。跨天仍必须指向最新一天。
- 已否决：重命名文件迎合字典序；放宽日期/索引检查；给 docs-gate 加白名单。

## 三、改动（文件级）

| 文件 | 改动 |
|---|---|
| `tools/check-docs-fresh.cjs` | 同日记录顺序只用于展示；指针校验改为 `targetRecord.date === latest.date`；不存在/跨天仍失败；注释说明 CI mtime 陷阱 |
| `docs/变更记录/2026-11/2026-11-13_文档门禁同日记录排序修复.md` | 本条记录 |
| `修改记录.md` / `docs/变更记录/README.md` | 最新一条 + 索引行 |
| `docs/交接文档.md` / `docs/README.md` | 门禁描述改为「最新日期（同日可并列）」；HEAD 指针 |
