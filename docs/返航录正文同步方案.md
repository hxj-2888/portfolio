## 2. 「正文 ↔ 代码同步」到底同步什么

返航录的规则与代码之间有三层一致性，**当前只做到第 1 层**：

| 层 | 内容 | 现状 | 目标 |
|---|---|---|---|
| L1 正文 → 站点 | PDF → `正文_规则.md` → `build_site.py` → `rules.html` | ✅ 有构建，但**抽取是人工触发的** | CI 里自动校验「PDF 变了但 md 没重抽」 |
| L2 正文 → 代码 | 规则条款编号（如 `2.8.15`、`6.8.3`、`7.3`）↔ 代码里的实现与测试断言 | ⚠️ 只有 570 条断言（`test:fix`），**没有条款覆盖率** | 覆盖率报告：每条规则是否被测试引用 |
| L3 代码 → 正文 | 代码里改了口径，正文没改 | ❌ 无检查 | `rules-map.json` + 校验脚本 |

### 2.1 建议的最小可行闭环（MVS）

1. **`docs/data/rules-map.json`**
   ```json
   {
     "version": "v1preview1.0",
     "source": { "pdf": "…", "md": "…", "pdf_sha256": "…", "md_sha256": "…" },
     "articles": {
       "2.8.15": { "title": "自指原则", "tests": ["test/fix/self-target.spec.js#…"] },
       "6.8.3":  { "title": "死囚变形", "tests": [] }
     }
   }
   ```
2. **`tools/check-rules-sync.cjs`**（新脚本，进 `npm run test:all`）
   - 校验 A：正文 md 的条款编号集合 ⊇ `rules-map.json` 的键（漏登记即失败）；
   - 校验 B：`rules-map.json` 里每个 `tests` 路径真实存在（悬空即失败）；
   - 校验 C：PDF 的 sha256 与 `source.pdf_sha256` 一致（**PDF 换了但没更新映射 → 失败**）；
   - 校验 D：站点产物 `rules.html` 里出现的条款数 ≥ 映射数（防「正文更新了、站点没重建」）。
3. **`npm run rules:coverage`**：输出「已覆盖条款 / 未覆盖条款」清单，未覆盖的按优先级补测试（先覆盖结算类：伤害、感染、停摆、驱逐、残局）。

### 2.2 追加素材（速查卡/术语表/流程图）怎么进站

- 文件放 `attachment-site/规则正文/`，与正文同名规范：`返航录三阵营对抗规则·<名称>v1preview1.0.pdf`；
- `build_site.py` 现有 `DOCS` 表支持 pdf 项：按「正文」同款方式**复制到 `site/` 并提供在线阅读/下载**；
- 附件站首页加一个「规则资料」卡片组（正文 / 速查卡 / 术语表 / 流程图），四个并列；
- 作品集的「过程」区块同步展示这四份（只在作品集里放链接，不放 PDF 本体，遵守「作品集不承载二进制」）。
