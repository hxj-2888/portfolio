## 一、仓库合成 / 静态门户（对应 `docs/GAME-ARCADE-方案.md`）

| 技巧 | 来源 | 关键结论 |
|---|---|---|
| 子目录部署的多应用，SW 必须**限制 scope 到相对路径**，并在 iframe 内禁用 | 你自己的 `sync.json` → `delta-force` 段 `patches`（已验证可用） | `register('sw.js?v=…', { scope: './' })` + `if (window.self !== window.top) return;`。**本方案直接复用，不新造轮子** |
| 子目录页面引用资源一律**相对路径** | 同上（`index.html` 4 条 regex 补丁 + `manifest.json` 的 `start_url/scope`） | 根绝对路径在子目录部署下会落到站点根 → 404 或劫持 |
| 多应用共用域名时，`localStorage` 配额与键名共享 | 你现有 `修改记录.md` 2026-08-29「四个子项目自动化同步核查结论」 | 两游戏键名独立，冲突风险低；回放数据是体积大头 |
| 白名单部署 + `neverCopy` 拦截 | 你的 `修改记录.md` 2026-08-29「统一 CI 与部署安全」 | 曾因缺 `projects.json` 导致线上 404；二进制不入库 |

**结论**：游戏包不需要新的开源参考，**照抄你自己两轮踩坑后固化的机制**最稳。

## 三、给本轮的 4 条结论

1. **游戏包不需要引入任何第三方框架**——你已有的 `sync.json` 补丁机制就是最合适的方案，第三方门户只会增加 CSP 与 SW 的边界问题。
2. **AI × Blender 的落地点是「MCP 客户端 + 本地 bpy 脚本」**，而不是在 Blender 里点按钮：你已经有 DSH，把它接到 Blender 上比装 addon 更可控，也更可留痕（每次 AI 生成的 bpy 脚本都进 git）。
3. **网页侧 AI 生成美术，最稳的是「离线生成 → 落地为静态资源 → 提交进 git」**，而不是运行时调 API（作品集 CSP 目前只允许 `'self'`）。
4. **返航录的「AI 判断逻辑优化」可以借 beehave 的行为树思路**（优先级 + 条件 + 中止），比继续堆 if-else 更可测、更好解释，也更容易写回归测试。
